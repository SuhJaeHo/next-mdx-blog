### RN WebView Bridge通信のPromiseベースAPI抽象化

React Native WebViewのメッセージベースBridge通信をPromiseベースの共通APIとして抽象化し、呼び出し側で一般的な非同期APIと同じ方法で使えるように改善しました。

- 既存のBridgeはリクエスト送信と応答イベント処理が分離されており、呼び出し元で応答値を直接受け取って後続処理を行ったり、リクエスト状態を管理することが難しい構造でした。
- BridgeリクエストをPromiseを返す共通関数として抽象化し、メッセージごとのリクエストパラメータと応答形式をTypeScriptの型として定義しました。
- リクエスト時に生成したmessage idを基準にPromiseのresolveを保存し、応答受信時に共通イベントハンドラーで同じidのresolveを探して実行するように構成しました。
- これにより呼び出し側は内部のpostMessageやイベント処理構造を知る必要なく、awaitベースの一般的な非同期APIのようにBridgeを利用できるようになりました。
- 共通Bridge関数をTanStack QueryのqueryFnと連携し、Native通信もサーバーAPIと同じようにローディング・エラー・応答データの状態を管理できるようにしました。

<CaseCodeDetails>
  <summary><span>Bridgeリクエスト・応答のPromise変換</span></summary>

```tsx
type RNBridgeMessageMap = {
  "get-is-use-biometric": {
    params: null;
    response: BridgeResponse;
  };
};

const pendingRequestsRef = useRef<
  Record<
    keyof RNBridgeMessageMap,
    {
      resolve: (response: BridgeResponse) => void;
      reject: (error: unknown) => void;
    }
  >
>({});

const callRN = useCallback(
  <K extends keyof RNBridgeMessageMap>(
    message: {
      id: K;
      params: RNBridgeMessageMap[K]["params"];
    }
  ): Promise<RNBridgeMessageMap[K]["response"]> => {
    return new Promise((resolve, reject) => {
      // メッセージidと該当リクエストのPromiseを紐付け
      pendingRequestsRef.current[message.id] = {
        resolve,
        reject,
      };

      window.ReactNativeWebView?.postMessage(
        JSON.stringify(message)
      );
    });
  },
  []
);

const handleMessage = useCallback((event: MessageEvent) => {
  const response = JSON.parse(event.data) as BridgeResponse;

  // Native応答のidに対応するPromiseを探索
  const pendingRequest =
    pendingRequestsRef.current[response.id];

  if (!pendingRequest) return;

  pendingRequest.resolve(response);
  delete pendingRequestsRef.current[response.id];
}, []);
```

- 共通コンポーネントとして構成することで、各画面では個別のジェスチャーロジックなしにPull-To-Refreshを適用できるようにしました。

各サービスでApp LauncherのUIと設定を個別に管理しており、共通変更時に複数のプロジェクトへ同じ作業を繰り返す必要がありました。

- サービス追加や表示情報変更時に各プロジェクトを修正せず、共通S3設定だけを変更すれば全サービスへ反映されるように改善しました。
