# BoardへのMDX統合

MDXはJSX構文を使えるように拡張されたMarkdownです。文章、Markdown構造、JavaScript式、コンポーネントを同じドキュメント処理パイプラインで扱えます。

このポートフォリオでは、MDXによってコンテンツとBoardのインタラクションコードを分離しています。タブは`contentFile`を保持し、選択されたファイルは`Board.TabContent`内でレンダリングされます。

## コンパイルパイプライン

処理を簡略化すると次のようになります。

1. **MarkdownとMDX構文をmdastへ解析**

   MarkdownノードとMDX固有ノードをMarkdown抽象構文木として表現します。

2. **remarkプラグインを実行**

   remarkプラグインはmdastを検査・変換します。`remark-gfm`は表やタスクリストなどGitHub Flavored Markdownの機能を追加します。

3. **mdastをhastへ変換**

   Markdown構造をHTML形式の抽象構文木へ変換し、MDXノードは後でJavaScriptやコンポーネント式にできるよう保持します。

4. **rehypeプラグインを実行**

   rehypeプラグインはhastを検査・変換します。このポートフォリオでは`rehype-prism-plus`でコードブロックにシンタックスハイライト情報を付けます。

5. **JavaScriptへコンパイル**

   MDXは最終的にJSXランタイムを使うJavaScriptになります。結果のモジュールをレンダリングするとReact要素が生成され、単純なHTML文字列を返す仕組みではありません。

## このポートフォリオでの読み込み方法

サーバーは静的生成時にMarkdownファイルを読み、シリアライズします。

```ts
import { serialize } from "next-mdx-remote/serialize";
import rehypePrism from "rehype-prism-plus";
import remarkGfm from "remark-gfm";

const source = await serialize(fileContent, {
  mdxOptions: {
    remarkPlugins: [remarkGfm],
    rehypePlugins: [rehypePrism],
    format: "mdx",
  },
});
```

シリアライズした結果をレンダラーへ渡します。

```tsx
import { MDXRemote } from "next-mdx-remote";

const components = { pre: CodeBlock };

export function CustomMDX({ source }) {
  return <MDXRemote {...source} components={components} />;
}
```

`serialize`は原文を、コンパイル済みコードとscope情報を持つシリアライズ可能なオブジェクトへ変換します。`MDXRemote`はJSXランタイムでそれを評価し、React要素をレンダリングします。このプロジェクトでは標準の`pre`要素を独自のコードブロックコンポーネントに置き換えています。

## タブとドキュメントの接続

Boardデータにはタブとドキュメントの関係だけを保存します。

```json
{
  "id": "portfolio-overview-tab",
  "groupId": "portfolio-group",
  "name": "Overview",
  "contentFile": "portfolio-overview.mdx"
}
```

レンダリング時に対象ドキュメントを取得します。

```ts
const contentFile = boardData.tab[selectedTabId].contentFile;
const mdxContent = mdxSources[contentFile];
```

この分離には次の利点があります。

- Board reducerがドキュメント内容を知る必要がありません。
- ドラッグやレイアウト処理を変更せずにドキュメントを追加できます。
- 同じBoardで履歴書、自己紹介書、パッケージドキュメント、学習ノートを表示できます。
- 現在のBoard状態を保ったまま、ロケール別ファイルへ切り替えられます。

## MDXコアコンパイラの利用

同じ考え方を`@mdx-js/mdx`で直接実装することもできます。

```tsx
import { compile, run } from "@mdx-js/mdx";
import * as runtime from "react/jsx-runtime";

const compiled = await compile(mdxContent, { outputFormat: "function-body" });
const { default: MDXContent } = await run(String(compiled), {
  ...runtime,
  baseUrl: import.meta.url,
});

return <MDXContent />;
```

`compile`はJavaScriptコードを含む仮想ファイルを返します。`run`は渡されたJSXランタイムでコードを評価します。ユーザーが入力したMDXを評価するとJavaScriptが実行される可能性があるため、信頼できる原文だけを使用する必要があります。

## RemarkとRehype

- **Remarkプラグイン**は主にMarkdown構文とmdastを処理します。
- **Rehypeプラグイン**は主にHTML形式の構造とhastを処理します。
- 違いは最終結果がMarkdownかHTMLかではなく、どの構文木を受け取るかにあります。

## セキュリティと保守

このポートフォリオは任意のユーザー入力ではなく、バージョン管理されたローカルMDXファイルだけを読み込みます。コンパイル済みMDXは実行可能なJavaScriptであるため、この信頼境界が重要です。

`next-mdx-remote`リポジトリは2026年4月から読み取り専用でアーカイブされています。現在の統合は動作しますが、将来はRSC向けAPIや継続的に保守されているMDXソリューションへの移行を検討できます。
