# Boardパッケージのビルドと公開

Boardは、並べ替え可能なタブを持つパネルを移動・サイズ変更できる、このポートフォリオのインタラクションモデルとして始まりました。再利用可能な基盤をポートフォリオのコンテンツから分離し、NPMパッケージとして公開しました。

[`group-tabs-layout` NPMページ](https://www.npmjs.com/package/group-tabs-layout)

## Rollupを選んだ理由

Rollupはコンポーネントライブラリに次の利点を提供します。

1. 標準的なES ModuleとCommonJSの出力を生成します。
2. モジュールグラフの静的解析によってツリーシェイキングを行います。
3. TypeScript、CommonJS依存関係、CSS、圧縮のための明確なプラグイン構成を提供します。

ツリーシェイキングだけで、すべての利用者に最小のバンドルが保証されるわけではありません。ES Moduleの境界を保ち、不要な副作用を避け、パッケージのメタデータを正しく宣言する必要があります。

## ビルド構成の役割

### `@rollup/plugin-typescript`

TypeScriptコンパイラでコードを変換し、診断情報を出力します。`declaration`を有効にすると型宣言ファイルも生成できます。CIでは、バンドルとは独立して型検査を理解・実行できるように`tsc --noEmit`も使用します。

### `@rollup/plugin-node-resolve`

Node方式でパッケージを解決し、Rollupが`node_modules`内の依存関係を見つけられるようにします。

### `@rollup/plugin-commonjs`

CommonJSモジュールを、Rollupが解析できるES Moduleへ変換します。

### Peer dependencyと`external`

Reactコンポーネントライブラリでは、ReactとReact DOMをpeer dependencyとして宣言します。利用側のアプリケーションがランタイムを提供するため、Reactの二重バンドルを防げます。

peer dependencyの宣言だけではRollupからの除外は保証されないため、ビルド設定でも`external`に指定します。

### PostCSS

`rollup-plugin-postcss`はimportされたスタイルを処理します。JavaScriptからCSSを注入する方法と、利用者が明示的にimportする別ファイルへ抽出する方法を選べます。

## Rollup設定

```js
import commonjs from "@rollup/plugin-commonjs";
import resolve from "@rollup/plugin-node-resolve";
import terser from "@rollup/plugin-terser";
import typescript from "@rollup/plugin-typescript";
import postcss from "rollup-plugin-postcss";

export default {
  input: "src/index.ts",
  external: ["react", "react-dom"],
  output: [
    { file: "dist/index.js", format: "esm", sourcemap: true },
    { file: "dist/index.cjs", format: "cjs", exports: "named", sourcemap: true },
  ],
  plugins: [
    resolve(),
    commonjs(),
    typescript({ tsconfig: "./tsconfig.build.json" }),
    postcss({ extract: "styles.css", minimize: true }),
    terser(),
  ],
};
```

この例ではBabelを使用していません。TypeScriptがモダンJavaScriptを直接出力できるため、役割が重なる変換処理を避けています。対象環境ごとの構文変換が必要な場合は、TypeScriptとBabelの責務を明確に分けます。

## TypeScriptビルド設定

```json
{
  "compilerOptions": {
    "target": "ES2019",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["DOM", "ES2020"],
    "jsx": "react-jsx",
    "declaration": true,
    "declarationDir": "dist/types",
    "emitDeclarationOnly": false,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

RollupのTypeScriptプラグインがJavaScriptと型宣言を同時に生成するため、`emitDeclarationOnly`は`false`です。型宣言を別の`tsc`処理で生成する場合は、その専用設定で`true`を使用します。

## パッケージのエントリーポイント

```json
{
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "peerDependencies": { "react": ">=18", "react-dom": ">=18" },
  "sideEffects": ["**/*.css"]
}
```

- `main`は従来のCommonJSエントリーポイントです。
- `module`はES Moduleビルドを示す一般的な規約です。
- `exports`は最新のNode.jsとバンドラーが使用する公開エントリーポイントのマップです。
- `types`はTypeScript型宣言の場所を示します。
- `files`は公開パッケージに含めるファイルを制限します。
- `sideEffects`はJavaScriptのツリーシェイキングを許可しつつ、CSS importを保持します。

公開前に`npm pack --dry-run`を実行すると、含まれるファイルを確認できます。
