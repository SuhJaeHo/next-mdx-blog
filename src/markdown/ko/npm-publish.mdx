# Board 패키지 빌드와 배포

Board는 이동과 크기 조절이 가능한 패널 안에서 탭을 재정렬하는 이 포트폴리오의 인터랙션 모델로 시작했습니다. 포트폴리오 콘텐츠와 재사용 가능한 기반을 분리한 뒤 NPM 패키지로 배포했습니다.

[`group-tabs-layout` NPM 페이지 보기](https://www.npmjs.com/package/group-tabs-layout)

## Rollup을 선택한 이유

Rollup은 컴포넌트 라이브러리에 다음과 같은 장점이 있습니다.

1. 표준 ES Module과 CommonJS 결과물을 생성합니다.
2. 모듈 그래프의 정적 분석을 통해 트리 셰이킹을 수행합니다.
3. TypeScript, CommonJS 의존성, CSS, 코드 압축을 위한 명확한 플러그인 체계를 제공합니다.

트리 셰이킹만으로 모든 사용자의 번들이 항상 최소화되는 것은 아닙니다. ES Module 경계를 유지하고 불필요한 부수 효과를 피하며 패키지 메타데이터를 정확하게 선언해야 효과적으로 동작합니다.

## 빌드 구성 요소의 역할

### `@rollup/plugin-typescript`

TypeScript 컴파일러로 코드를 변환하고 진단 정보를 제공합니다. `declaration`을 활성화하면 타입 선언 파일도 생성할 수 있습니다. CI에서는 번들링과 타입 검사를 독립적으로 이해하고 강제할 수 있도록 `tsc --noEmit`도 별도로 실행합니다.

### `@rollup/plugin-node-resolve`

Node 방식으로 패키지를 해석해 Rollup이 `node_modules`의 의존성을 찾도록 합니다.

### `@rollup/plugin-commonjs`

CommonJS 모듈을 Rollup이 분석할 수 있는 ES Module로 변환합니다.

### Peer dependency와 `external`

React 컴포넌트 라이브러리의 React와 React DOM은 peer dependency로 선언해야 합니다. 사용하는 애플리케이션이 런타임을 제공하므로 React가 중복 번들링되는 것을 방지할 수 있습니다.

peer dependency 선언만으로 Rollup의 제외가 보장되지는 않으므로 빌드 설정에서도 `external`로 지정해야 합니다.

### PostCSS

`rollup-plugin-postcss`는 가져온 스타일을 처리합니다. 패키지 계약에 따라 JavaScript에서 CSS를 주입하거나 사용자가 직접 가져오는 별도 파일로 추출할 수 있습니다.

## Rollup 설정

```js
import commonjs from "@rollup/plugin-commonjs";
import resolve from "@rollup/plugin-node-resolve";
import terser from "@rollup/plugin-terser";
import typescript from "@rollup/plugin-typescript";
import postcss from "rollup-plugin-postcss";

export default {
  input: "src/index.ts",
  external: ["react", "react-dom"],
  output: [
    { file: "dist/index.js", format: "esm", sourcemap: true },
    { file: "dist/index.cjs", format: "cjs", exports: "named", sourcemap: true },
  ],
  plugins: [
    resolve(),
    commonjs(),
    typescript({ tsconfig: "./tsconfig.build.json" }),
    postcss({ extract: "styles.css", minimize: true }),
    terser(),
  ],
};
```

이 설정에서는 Babel을 사용하지 않습니다. TypeScript가 최신 JavaScript를 직접 생성하므로 역할이 겹치는 두 변환 과정을 피할 수 있습니다. 대상 환경별 문법 변환이 필요하다면 TypeScript와 Babel의 책임을 명확하게 나눠야 합니다.

## TypeScript 빌드 설정

```json
{
  "compilerOptions": {
    "target": "ES2019",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["DOM", "ES2020"],
    "jsx": "react-jsx",
    "declaration": true,
    "declarationDir": "dist/types",
    "emitDeclarationOnly": false,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

이 설정은 Rollup의 TypeScript 플러그인이 JavaScript와 타입 선언을 함께 만들기 때문에 `emitDeclarationOnly`를 `false`로 둡니다. 선언 파일을 별도의 `tsc` 단계에서 만든다면 전용 설정에서 `true`를 사용합니다.

## 패키지 진입점

```json
{
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "peerDependencies": { "react": ">=18", "react-dom": ">=18" },
  "sideEffects": ["**/*.css"]
}
```

- `main`은 기존 CommonJS 진입점입니다.
- `module`은 ES Module 빌드를 가리키는 널리 쓰이는 규칙입니다.
- `exports`는 최신 Node.js와 번들러가 사용하는 공개 진입점 지도입니다.
- `types`는 TypeScript 타입 선언의 위치를 지정합니다.
- `files`는 배포 패키지에 포함할 파일을 제한합니다.
- `sideEffects`는 JavaScript 트리 셰이킹을 허용하면서 CSS 가져오기를 보존합니다.

배포 전 `npm pack --dry-run`으로 실제 포함 파일을 확인할 수 있습니다.
