# Board에 MDX 통합하기

MDX는 JSX 문법을 사용할 수 있도록 확장된 Markdown입니다. 글, Markdown 구조, JavaScript 표현식, 컴포넌트를 하나의 문서 처리 과정에서 함께 다룰 수 있습니다.

이 포트폴리오에서는 MDX로 콘텐츠와 Board 인터랙션 코드를 분리했습니다. 탭은 `contentFile`을 저장하고 선택된 파일은 `Board.TabContent` 안에서 렌더링됩니다.

## 컴파일 과정

단순화한 처리 과정은 다음과 같습니다.

1. **Markdown과 MDX 문법을 mdast로 해석**

   Markdown 노드와 MDX 전용 노드를 Markdown 추상 구문 트리로 표현합니다.

2. **remark 플러그인 실행**

   remark 플러그인은 mdast를 검사하거나 변환합니다. `remark-gfm`은 표와 작업 목록 등 GitHub Flavored Markdown 문법을 지원합니다.

3. **mdast를 hast로 변환**

   Markdown 구조를 HTML 형태의 추상 구문 트리로 변환하고 MDX 노드는 이후 JavaScript와 컴포넌트 표현식이 될 수 있도록 보존합니다.

4. **rehype 플러그인 실행**

   rehype 플러그인은 hast를 검사하거나 변환합니다. 이 포트폴리오는 `rehype-prism-plus`로 코드 블록에 구문 강조 정보를 추가합니다.

5. **JavaScript로 컴파일**

   MDX는 최종적으로 JSX 런타임을 사용하는 JavaScript가 됩니다. 결과 모듈을 렌더링하면 React 요소가 생성되며 단순한 HTML 문자열을 반환하는 방식이 아닙니다.

## 이 포트폴리오에서 MDX를 불러오는 방법

서버는 정적 생성 단계에서 Markdown 파일을 읽고 직렬화합니다.

```ts
import { serialize } from "next-mdx-remote/serialize";
import rehypePrism from "rehype-prism-plus";
import remarkGfm from "remark-gfm";

const source = await serialize(fileContent, {
  mdxOptions: {
    remarkPlugins: [remarkGfm],
    rehypePlugins: [rehypePrism],
    format: "mdx",
  },
});
```

직렬화된 결과는 렌더러에 전달합니다.

```tsx
import { MDXRemote } from "next-mdx-remote";

const components = { pre: CodeBlock };

export function CustomMDX({ source }) {
  return <MDXRemote {...source} components={components} />;
}
```

`serialize`은 원문을 컴파일된 코드와 scope 정보가 포함된 직렬화 가능한 객체로 바꿉니다. `MDXRemote`는 JSX 런타임으로 이를 평가해 React 요소를 렌더링합니다. 이 프로젝트는 기본 `pre` 요소를 자체 코드 블록 컴포넌트로 교체합니다.

## 탭과 문서 연결

Board 데이터에는 탭과 문서의 관계만 저장합니다.

```json
{
  "id": "portfolio-overview-tab",
  "groupId": "portfolio-group",
  "name": "Overview",
  "contentFile": "portfolio-overview.mdx"
}
```

렌더링 시점에는 다음과 같이 문서를 찾습니다.

```ts
const contentFile = boardData.tab[selectedTabId].contentFile;
const mdxContent = mdxSources[contentFile];
```

이 구조에는 다음과 같은 장점이 있습니다.

- Board reducer가 문서 내용을 알 필요가 없습니다.
- 드래그와 레이아웃 로직을 바꾸지 않고 문서를 추가할 수 있습니다.
- 같은 Board에서 이력서, 자기소개서, 패키지 문서, 학습 기록을 렌더링할 수 있습니다.
- 활성 Board 상태를 유지하면서 로케일별 문서로 교체할 수 있습니다.

## MDX 핵심 컴파일러 사용

같은 개념을 `@mdx-js/mdx`로 직접 구현할 수도 있습니다.

```tsx
import { compile, run } from "@mdx-js/mdx";
import * as runtime from "react/jsx-runtime";

const compiled = await compile(mdxContent, { outputFormat: "function-body" });
const { default: MDXContent } = await run(String(compiled), {
  ...runtime,
  baseUrl: import.meta.url,
});

return <MDXContent />;
```

`compile`은 JavaScript 코드가 담긴 가상 파일을 반환합니다. `run`은 전달받은 JSX 런타임으로 코드를 평가합니다. 사용자 입력 MDX를 평가하면 JavaScript가 실행될 수 있으므로 신뢰할 수 있는 원문만 사용해야 합니다.

## Remark와 Rehype

- **Remark 플러그인**은 주로 Markdown 문법과 mdast를 처리합니다.
- **Rehype 플러그인**은 주로 HTML 형태의 구조와 hast를 처리합니다.
- 차이는 최종 결과가 Markdown인지 HTML인지가 아니라 어떤 구문 트리를 전달받는지에 있습니다.

## 보안과 유지보수

이 포트폴리오는 사용자가 입력한 임의의 문서가 아니라 버전 관리되는 로컬 MDX 파일만 불러옵니다. 컴파일된 MDX는 실행 가능한 JavaScript이므로 이 신뢰 경계가 중요합니다.

`next-mdx-remote` 저장소는 2026년 4월부터 읽기 전용으로 보관되고 있습니다. 현재 연동은 정상 동작하지만 향후에는 RSC 중심 API나 유지보수 중인 다른 MDX 솔루션으로의 이전을 검토할 수 있습니다.
