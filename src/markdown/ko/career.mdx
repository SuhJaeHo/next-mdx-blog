### RN WebView Bridge 통신의 Promise 기반 API 추상화

React Native WebView의 메세지 기반 Bridge 통신을 Promise 기반 공통 API로 추상화해, 호출부에서 일반적인 비동기 API와 동일한 방식으로 사용할 수 있도록 개선했습니다.

- 기존 Bridge는 요청 전송과 응답 이벤트 처리가 분리되어 있어, 호출한 위치에서 응답값을 직접 받아 후속 로직을 처리하거나 요청 상태를 관리하기 어려웠습니다.
- Bridge 요청을 Promise를 반환하는 공통 함수로 추상화하고, 메세지별 요청 파라미터와 응답 형식을 TypeScript 타입으로 정의했습니다.
- 요청 시 생성한 message id를 기준으로 Promise의 resolve를 저장하고, 응답 수신 시 공통 이벤트 핸들러에서 동일한 id의 resolve를 찾아 실행하도록 구성했습니다.
- 이를 통해 호출부에서는 내부의 postMessage 및 이벤트 처리 구조를 알 필요 없이 await 기반의 일반 비동기 API처럼 Bridge를 사용할 수 있도록 했습니다.
- 공통 Bridge 함수를 TanStack Query의 queryFn과 연동해 Native 통신도 서버 API와 동일하게 로딩·에러·응답 데이터 상태를 관리할 수 있도록 구성했습니다.

```tsx
type RNBridgeMessageMap = {
  "get-is-use-biometric": {
    params: null;
    response: BridgeResponse;
  };
};

const pendingRequestsRef = useRef<
  Record<
    keyof RNBridgeMessageMap,
    {
      resolve: (response: BridgeResponse) => void;
      reject: (error: unknown) => void;
    }
  >
>({});

const callRN = useCallback(
  <K extends keyof RNBridgeMessageMap>(
    message: {
      id: K;
      params: RNBridgeMessageMap[K]["params"];
    }
  ): Promise<RNBridgeMessageMap[K]["response"]> => {
    return new Promise((resolve, reject) => {
      // 메세지 id와 해당 요청의 Promise를 연결
      pendingRequestsRef.current[message.id] = {
        resolve,
        reject,
      };

      window.ReactNativeWebView?.postMessage(
        JSON.stringify(message)
      );
    });
  },
  []
);

const handleMessage = useCallback((event: MessageEvent) => {
  const response = JSON.parse(event.data) as BridgeResponse;

  // Native 응답의 id로 대응되는 Promise 탐색
  const pendingRequest =
    pendingRequestsRef.current[response.id];

  if (!pendingRequest) return;

  pendingRequest.resolve(response);
  delete pendingRequestsRef.current[response.id];
}, []);
```

### 이벤트 위임 기반 햅틱 피드백 공통화

WebView에서 버튼마다 햅틱 처리를 직접 구현할 경우 UI 컴포넌트와 Native Bridge 호출 로직 간의 결합도가 높아지고, 동일한 이벤트 처리 코드가 반복되는 문제가 있었습니다.

- 햅틱이 필요한 요소에는 data-haptic 속성만 선언하고, 공통 터치 이벤트 리스너에서 해당 속성을 기준으로 햅틱을 처리하는 이벤트 위임 구조로 변경했습니다.
- 공통 핸들러에서는 터치가 종료된 요소에서 data-haptic 속성을 탐색해 필요한 햅틱 타입을 확인하고 Bridge 요청을 하도록 구성하였습니다.
- 이를 통해 개별 컴포넌트에서는 Bridge 호출이나 이벤트 리스너를 직접 관리하지 않고 HTML 속성만으로 햅틱 동작을 선언할 수 있도록 했으며, 동적으로 추가되는 요소에도 동일한 규칙을 적용할 수 있었습니다.
- 터치 시작 시점의 좌표를 저장하고 이동 거리를 계산해 일정 임계값을 초과하면 스크롤 또는 드래그로 판단하도록 구현했습니다.
- 스크롤·드래그로 판단된 경우 터치 종료 시에도 햅틱을 실행하지 않도록 하여 스크롤 과정에서 발생하는 의도하지 않은 햅틱을 방지했습니다.
