## 실시간 거래 서비스의 성능 개선과 안정적 운영

위메이드에서는 오더북 기반 게임 토큰 거래소의 웹 프론트엔드 개발에 참여했습니다. 소규모 팀에서 초기 설계부터 출시와 운영까지 경험했으며, 담당 인력이 변경된 상황에서도 기존 구조와 거래 로직을 빠르게 파악해 남은 팀원과 서비스를 지속적으로 운영했습니다.

특히 실시간 시세와 오더북처럼 대량의 데이터가 지속적으로 유입되는 화면의 성능 개선을 담당했습니다. WebSocket 데이터를 버퍼링하고 일정 주기로 일괄 반영해 불필요한 렌더링을 줄였으며, React의 동시성 기능을 활용해 업데이트 우선순위를 분리했습니다. 그 결과 대규모 트래픽을 가정한 테스트에서도 안정적인 화면 응답성을 유지할 수 있었습니다.

이 경험을 통해 프론트엔드는 단순히 화면을 구현하는 역할이 아니라, 네트워크와 데이터 흐름, 브라우저 렌더링을 함께 고려해 사용자가 체감하는 안정성을 만드는 역할이라는 점을 배웠습니다.

## 상황에 맞는 구조를 선택하는 실용적인 개발

넥써쓰에서는 지갑, 거래소, 퍼블릭 세일, 스테이킹처럼 성격이 다른 서비스를 개발했습니다. 가장 복잡하거나 새로운 구조보다 현재 일정, 팀 구성, 운영 환경에 적합한 구조를 선택하는 것을 중요하게 생각했습니다.

퍼블릭 세일 서비스에서는 **일주일 안에 프로젝트 설정부터 지갑 연결, KYC, RPC 설정, 컨트랙트 호출까지 구현**했습니다. 운영 중 퍼블릭 RPC의 Rate Limit으로 데이터 조회가 지연되자 원인을 분석하고 JWT 인증 기반 프라이빗 RPC로 전환했습니다. 해당 서비스는 **약 200억 원 규모의 세일을 중대한 장애 없이 완료**했습니다.

토큰 거래소에서는 **중복된 트랜잭션 처리 로직을 adapter 구조로 통합**하고 모노레포에서 독립 프로젝트로 마이그레이션했습니다. Swagger 명세를 기반으로 DTO·Entity·Repository를 생성하는 구조도 구축했습니다. 이러한 개선을 통해 기존 기능을 유지하면서 **전체 코드량을 약 30% 줄였습니다.**

저에게 실용적인 개발이란 특정 기술이나 설계를 고집하는 것이 아닙니다. 불필요한 추상화와 과도한 복잡성을 피하면서 변경과 유지보수가 쉬운 구조를 선택하는 것입니다.

저의 강점은 **낯선 구조를 빠르게 이해하고, 문제를 해결 가능한 단위로 나누며, 정해진 일정 안에 실제로 동작하는 제품을 완성하는 것**입니다.

단순히 주어진 기능을 구현하는 데 그치지 않고, 일정과 품질의 균형을 고려해 팀이 안정적으로 결과물을 완성하는 데 기여하는 개발자가 되는 것이 목표입니다. AI 도구도 단순한 코드 생성 수단이 아니라 요구사항 분석, 반복 작업 자동화, 테스트 코드 작성과 코드 검토에 적극적으로 활용해 개발 생산성과 결과물의 완성도를 높이겠습니다.

장기적으로는 프론트엔드와 백엔드의 경계를 넘어 기술적 의사결정에 참여하고, 다양한 도메인에서 사용자가 만족할 수 있는 안정적이고 편리한 서비스를 만드는 소프트웨어 엔지니어로 성장하겠습니다.
