# Building and Publishing the Board Package

The Board began as the interaction model behind this portfolio: movable and resizable groups containing reorderable tabs. I separated the reusable foundation from the portfolio content and published it as an NPM package.

[`group-tabs-layout` on NPM](https://www.npmjs.com/package/group-tabs-layout)

## Why Rollup

Rollup is a good fit for a component library because it:

1. Produces standard ES module and CommonJS outputs
2. Performs tree-shaking through static analysis of the module graph
3. Provides a focused plugin system for TypeScript, CommonJS dependencies, CSS, and minification

Tree-shaking is not automatic proof that every consumer receives the smallest possible bundle. It works best when the library preserves ES module boundaries, avoids unnecessary side effects, and declares package metadata correctly.

## Build Responsibilities

### `@rollup/plugin-typescript`

Uses the TypeScript compiler to transpile TypeScript and report compiler diagnostics. It can also emit declaration files when `declaration` is enabled. I still run `tsc --noEmit` separately in CI because an explicit type-check command is easier to understand and enforce independently from bundling.

### `@rollup/plugin-node-resolve`

Resolves packages using Node-style resolution so Rollup can locate dependencies imported from `node_modules`.

### `@rollup/plugin-commonjs`

Converts CommonJS modules into ES modules that Rollup can analyze. Rollup itself is centered on ES modules, so this plugin is useful when a dependency only exposes CommonJS.

### Peer dependencies and `external`

React and React DOM should be peer dependencies of a React component library. The consuming application supplies them, which prevents the package from bundling a second React runtime.

Declaring a peer dependency does not, by itself, guarantee that Rollup excludes it. The build should also mark it as `external` (or use a plugin that derives externals from `peerDependencies`).

### PostCSS

`rollup-plugin-postcss` processes imported styles. Depending on the package contract, CSS can be injected by JavaScript or extracted into a separate file that consumers import explicitly.

## Corrected Rollup Configuration

```js
import commonjs from "@rollup/plugin-commonjs";
import resolve from "@rollup/plugin-node-resolve";
import terser from "@rollup/plugin-terser";
import typescript from "@rollup/plugin-typescript";
import postcss from "rollup-plugin-postcss";

export default {
  input: "src/index.ts",
  external: ["react", "react-dom"],
  output: [
    {
      file: "dist/index.js",
      format: "esm",
      sourcemap: true,
    },
    {
      file: "dist/index.cjs",
      format: "cjs",
      exports: "named",
      sourcemap: true,
    },
  ],
  plugins: [
    resolve(),
    commonjs(),
    typescript({ tsconfig: "./tsconfig.build.json" }),
    postcss({
      extract: "styles.css",
      minimize: true,
    }),
    terser(),
  ],
};
```

This example intentionally omits Babel. TypeScript can emit modern JavaScript directly, which avoids running two overlapping transpilation pipelines. Babel is still useful when a library needs target-specific syntax transforms; in that case, `@babel/preset-typescript` or a clearly separated TypeScript/Babel responsibility is required.

## TypeScript Build Configuration

```json
{
  "compilerOptions": {
    "target": "ES2019",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["DOM", "ES2020"],
    "jsx": "react-jsx",
    "declaration": true,
    "declarationDir": "dist/types",
    "emitDeclarationOnly": false,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

`emitDeclarationOnly` is `false` because this configuration asks the TypeScript Rollup plugin to produce JavaScript as well as declarations. If declarations are generated in a separate `tsc` step, then `emitDeclarationOnly: true` belongs in that separate declaration-specific configuration.

## Package Entry Points

A modern package should expose its public API explicitly:

```json
{
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "peerDependencies": {
    "react": ">=18",
    "react-dom": ">=18"
  },
  "sideEffects": ["**/*.css"]
}
```

- `main` is the legacy CommonJS entry point.
- `module` is a widely supported convention for the ES module build.
- `exports` is the authoritative public entry-point map for modern Node.js and bundlers.
- `types` points TypeScript to the package declarations.
- `files` limits the files included in the published package.
- `sideEffects` preserves CSS imports while allowing JavaScript tree-shaking.

Before publishing, `npm pack --dry-run` is useful for checking exactly which files will be included.
