# Publishing a Chrome-like Group Tab Component Package

I separated Chrome-like group tab interactions and resizing logic from the content, turning them into a reusable component package. I configured a Rollup-based build pipeline and published the package to <a className="npm-inline-link" href="https://www.npmjs.com/package/group-tabs-layout" target="_blank" rel="noreferrer">NPM</a> with type declarations and style output so the same tab and panel interactions can be used in other projects.

## Why Rollup

Rollup is a good fit for a component library because it:

1. Produces standard ES module and CommonJS outputs
2. Performs tree-shaking through static analysis of the module graph
3. Provides a focused plugin system for TypeScript, CommonJS dependencies, CSS, and minification

Tree-shaking is not automatic proof that every consumer receives the smallest possible bundle. It works best when the library preserves ES module boundaries, avoids unnecessary side effects, and declares package metadata correctly.

## Rollup Plugin Configuration and Responsibilities

<div className="code-explanation-list">
  <div><strong>@rollup/plugin-typescript</strong><span>Uses the TypeScript compiler to transpile TypeScript and report compiler diagnostics. It can also emit declaration files when declaration is enabled.</span></div>
  <div><strong>@rollup/plugin-node-resolve</strong><span>Resolves packages using Node-style resolution so Rollup can locate dependencies imported from node_modules.</span></div>
  <div><strong>@rollup/plugin-commonjs</strong><span>Converts CommonJS modules into ES modules that Rollup can analyze.</span></div>
  <div><strong>Peer dependencies and external</strong><span>React and React DOM should be peer dependencies, and the consuming application supplies them, which prevents the package from bundling a second React runtime. Declaring a peer dependency does not, by itself, guarantee that Rollup excludes it, so the build should also mark it as external.</span></div>
  <div><strong>rollup-plugin-postcss</strong><span>Processes imported styles. Depending on the package contract, CSS can be injected by JavaScript or extracted into a separate file that consumers import explicitly.</span></div>
</div>

## Rollup Configuration

```js
import commonjs from "@rollup/plugin-commonjs";
import resolve from "@rollup/plugin-node-resolve";
import terser from "@rollup/plugin-terser";
import typescript from "@rollup/plugin-typescript";
import postcss from "rollup-plugin-postcss";

export default {
  input: "src/index.ts",
  external: ["react", "react-dom"],
  output: [
    { file: "dist/index.js", format: "esm", sourcemap: true },
    { file: "dist/index.cjs", format: "cjs", exports: "named", sourcemap: true },
  ],
  plugins: [
    resolve(),
    commonjs(),
    typescript({ tsconfig: "./tsconfig.build.json" }),
    postcss({ extract: "styles.css", minimize: true }),
    terser(),
  ],
};
```

```json
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"

    "./styles.css": "./dist/styles.css"

  "files": ["dist"],
  "peerDependencies": {
    "react": ">=18",
    "react-dom": ">=18"
  },
  "sideEffects": ["**/*.css"]
}
```
